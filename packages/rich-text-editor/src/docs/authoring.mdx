# Writing a plugin

A plugin adds a mark, a block or an inline element to the editor. A mark styles a run of text, such as bold. A block is a paragraph-sized unit, such as a quote. An inline is a small element inside a line of text, such as a mention.

Every example on this page is real code. The excerpts are copied from the file named in the line above each one.

## A mark in one file

A feature has two parts. The content (`defineContent`) says what a document can hold and how each node is written as HTML and read back. The plugin (`definePlugin`) adds the editing on top: toolbar buttons, keys and typing rules.

Keep them apart because the renderer reads only the content. A page that shows documents keeps the content and drops the plugin with its editing code. Mark the `definePlugin` call `/* @__PURE__ */` so the bundler can drop it.

Source: `src/stories/PluginExamples.stories.tsx`

```tsx
const acmeHighlightContent = defineContent({
    marks: {
        'acme-highlight': defineMark({
            toHtml: () => ({
                tag: 'mark',
                attrs: {
                    class: 'tw-rounded-small tw-bg-container-warning tw-text-container-warning-on-warning-container',
                },
                children: true,
            }),
            parse: [{ tag: 'mark' }],
        }),
    },
});
```

Source: `src/stories/PluginExamples.stories.tsx`

```tsx
const acmeHighlightPlugin = /* @__PURE__ */ definePlugin({
    content: acmeHighlightContent,
    toolbar: [
        {
            label: 'Highlight',
            render: ({ api, selection, label }) => {
                const active = selection.marks['acme-highlight']?.coverage === 'all';
                return (
                    <button
                        type="button"
                        aria-pressed={active}
                        onMouseDown={(event) => event.preventDefault()}
                        onClick={() => api.marks.toggle('acme-highlight')}
                        className={toolbarButtonClasses(active)}
                    >
                        {label}
                    </button>
                );
            },
        },
    ],
    hotkeys: { 'Mod-Shift-h': { label: 'Highlight', run: (api) => api.marks.toggle('acme-highlight') } },
});
```

`definePlugin` takes its `id` from the only type the content declares. With several types, give it an `id`.

`toolbarButtonClasses` is the story's own styling. Use your own classes in its place.

Pass the plugin to the editor and the content to the renderer.

```tsx
<RichTextEditor plugins={[...defaultPlugins, acmeHighlightPlugin]} value={doc} onChange={setDoc} />
<RichTextRenderer plugins={[...defaultContent, acmeHighlightContent]} value={doc} />
```

## A block and an inline

A block uses `defineBlock`. Its `content` says what it holds: `'text'` for text and inlines, `{ items }` for a list, `{ blocks }` for other blocks. Leave it out for a block with nothing to edit.

Source: `src/stories/PluginExamples.stories.tsx`

```tsx
const acmeCalloutContent = defineContent({
    blocks: {
        'acme-callout': defineBlock({
            content: 'text',
            toHtml: () => ({
                tag: 'aside',
                attrs: {
                    class: 'tw-m-0 tw-rounded-medium tw-border tw-border-solid tw-border-warning tw-bg-container-warning tw-px-3 tw-py-2',
                },
                children: true,
            }),
            parse: [{ tag: 'aside' }],
        }),
    },
});
```

<Canvas of={PluginExamples.ConsumerBlock} />

An inline uses `defineInline`. It has no text of its own. Its value, here the provider, is stored flat on the document node. Give the type argument to type that value.

Source: `src/stories/PluginExamples.stories.tsx`

```tsx
const acmeEmbedContent = defineContent({
    inlines: {
        'acme-embed': defineInline<EmbedValue>({
            toHtml: ({ provider }) => ({
                tag: 'span',
                attrs: { 'data-embed': provider, class: embedClasses },
                children: `▤ ${provider}`,
            }),
            parse: [{ tag: 'span[data-embed]', value: (element) => ({ provider: element.dataset.embed ?? '' }) }],
        }),
    },
});
```

This story also gives the plugin an `edit` view, a component that draws the inline while it has no value. See `acmeEmbedPlugin` in the same file.

## Toolbar entries and hotkeys

A plugin lists its toolbar controls in `toolbar`. Each entry is data:

- `label` is required. It is the button's accessible name, its tooltip and, when the entry sets `menu`, its name in the `/` menu.
- `icon` is the button's icon, a component such as one from `@frontify/fondue-icons`.
- `shortcut` is a key in `Mod-b` style. The tooltip shows it, and it toggles the entry's type.
- `toggles` names the mark, block or inline the entry turns on and off. It defaults to the only type the content declares.
- `render` draws custom UI in place of the button. It gets the `api`, the `selection`, the entry's `label` to name it with, and a `toggle` function. An entry has an `icon` or a `render`.

`toolbarGroup`, on the plugin, picks the toolbar cluster its entries sit in, such as `'marks'` or `'insert'`. A plugin without one sits after the built-in groups.

Source: `src/plugins/Underline/Underline.ts`

```ts
export const underlinePlugin = /* @__PURE__ */ definePlugin({
    content: underlineContent,
    toolbarGroup: 'marks',
    toolbar: [{ label: 'Underline', icon: IconTextFormatUnderline, shortcut: 'Mod-u' }],
});
```

For a key with its own action, use `hotkeys`, as the highlight plugin above does. Each binding needs a `label` and a `run` function. `Mod` is Cmd on macOS and Ctrl elsewhere. Avoid keys the system or browser takes, such as `Mod-h`, which hides the app on macOS.

The label is not optional. The [Keyboard reference](?path=/docs/rich-text-editor-guides-keyboard-reference--docs) page is written from these labels and the toolbar shortcuts, so a plugin that gains a key appears there with no edit to that page.

## Parse rules and HTML output

Every definition says how it is written and how it is read back.

- `toHtml` takes the node's value and returns an `HtmlSpec`: a `tag`, optional `attrs` and `children`. `children: true` is where the node's content goes. A string is fixed content.
- `parse` is a list of rules that read pasted HTML back into the node. A rule has a `tag`, a CSS selector such as `a[href]`. Its optional `value` function reads the value from the element, or returns `null` when the element is not this node after all.

A mark that is only a tag can skip both with `defineMark({ tag: 'u' })`. A mark also takes parse rules for inline styles, as Google Docs writes them. A `style` rule matches an element that declares that CSS property, and its `value` function gets the declared value.

Source: `src/plugins/Underline/Underline.ts`

```ts
export const underlineContent = defineContent({
    marks: {
        underline: defineMark({
            tag: 'u',
            // A decorated element counts too, as Google Docs writes it; `text-decoration: none` never removes it, as in a browser.
            parse: [{ tag: 'u' }, ...decorationLineRules('underline')],
        }),
    },
});
```

## Naming your types

Prefix the type names you store with your own namespace: `acme-callout`, `acme-highlight`, `acme-embed`. A stored type is part of your documents for good. The package may ship a `callout` or a `highlight` later, and an unprefixed type would then clash with it.

Every example above follows this rule. The prefix is in the stored type and the mark key. The toolbar `label` is what people read, so it stays plain.
