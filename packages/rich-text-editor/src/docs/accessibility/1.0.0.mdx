# Accessibility report 1.0.0

This report follows the layout of the ITI VPAT INT edition, with an ATAG 2.0 annex. It covers WCAG 2.2 Level A and AA, the two AAA targets 2.1.3 and 2.4.13, and ATAG 2.0 Part A and Part B at Level AA. The EN 301 549 clause 9 and Revised Section 508 web criteria are the WCAG 2.2 tables below. The EN 301 549 clause 11.8 and Section 508 504 authoring tool criteria rest on the ATAG 2.0 annex. The functional performance criteria of EN 301 549 clause 4 and Section 508 chapter 3 describe use with assistive technology, which no test of this release ran, so they are Not Evaluated.

Every mark rests on automated tests in this repository alone. No screen reader, real device or person took part. No mark is taken from ProseMirror, Radix or another vendor.

Each row names the WCAG criterion and the specs that verify it, as paths relative to the package. A row that reads "no automated test" has none.

The conformance levels mean:

- **Supports**: every test behind the row passed.
- **Partially Supports**: the tests passed, and the row says which configurations they do not cover.
- **Does Not Support**: a test behind the row failed.
- **Not Applicable**: nothing in the package can meet or fail the criterion, or the host page owns it.
- **Not Evaluated**: only a screen reader, a real device or a person can show the outcome, or the criterion has no automated test in this release. The remark says which.

## Tested configuration

- **Package**: `@frontify/fondue-rich-text-editor` 1.0.0, tested at commit `51a7e5b62ecdba50702dd4128b040b1564fcf195`.
- **Profiles**: Inline, Comment, Document and Brand document, each through its story under `Rich Text Editor/Profiles`, which is the reference workflow story, plus every feature story.
- **Browsers**: Playwright 1.60.0 component tests in Chromium 148.0.7778.96 and WebKit 26.4. Firefox 150.0.2 runs in the Component Tests and Engine Qualification jobs of the pull request workflow. A criterion whose test fails in Firefox changes to Does Not Support before the release.
- **Theme**: the light theme. axe-core 4.13.0 checks the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`.
- **Unit tests**: Vitest in `happy-dom` and Node.
- **People and devices**: none. No screen reader, voice control, switch control, on-screen keyboard, real phone or tablet, and no person took part.

## Limitations and host-owned criteria

- **No assistive technology or device.** No screen reader, voice control, switch control, on-screen keyboard, dictation, real phone or tablet ran. So 1.3.1, 2.4.11, 4.1.2, 4.1.3 and A.2.2.2 are Not Evaluated, and composition is tested in Chromium only. A host that needs such a claim runs its own evaluation.
- **Criteria without an automated test in this release.** Images of text (1.4.5) and search in the editing view (A.3.5.1). Their rows say "no automated test".
- **Dark theme.** The axe and layout tests run in the light theme.
- **Features that ship in 1.x.** Tables, embeds, highlight, find and replace and the block handle are not in any 1.0 profile. The Limitations guide lists them. Their requirements are not part of this report.
- **Content checks per profile.** Inline and Comment install no content checks, so Part B section 3 and B.4.1 are Partially Supports.
- **Host-owned criteria.** The host page owns 2.4.1 Bypass Blocks, 2.4.2 Page Titled, 2.4.5 Multiple Ways, the page `lang` of 3.1.1, and 3.3.4 Error Prevention, since it owns submission. The host owns the asset picker of B.2.5.1 and B.2.5.2.

## Editing and published output

An author meets more than a reader of the published output. The reader and `toHTML` output have the same text, roles, link targets and alternative texts as the editor, apart from these:

- **The editing surface** is one `role="textbox"` with `aria-multiline`, `aria-invalid`, `aria-required`, `aria-disabled` and a description of its keys. The reader output is plain document markup.
- **Node chrome**, such as the image toolbar, the code language menu and the upload controls, exists only while editing.
- **Content check decorations** outline issues in the surface while the issues panel is open. The output holds none of them.
- **An image without an alternative text decision** shows "Add alternative text" while editing. The output writes no `alt` for it, so the checks report it.
- **A link that opens a new window** says so in the reader only.
- **Content the model does not know** stays an island while editing. The reader shows a labelled fallback with its text and one notice for the document.
